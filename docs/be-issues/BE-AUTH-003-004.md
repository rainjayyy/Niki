## 背景

BE-AUTH-001 提供 JWT 签发/校验；BE-AUTH-002 提供 SMS 登录发 token。前端拿到 access_token 后还有两个生命周期痛点：

1. **1 小时过期后强制重新登录** —— 用户每用 1 小时要重新 SMS，UX 崩溃
2. **无法主动注销** —— 设备丢了 / 改账号了，旧 token 仍在生效（除非等到 1 小时自然过期）

## 验收标准（AC）

- [ ] AC-1：`POST /api/v1/auth/refresh` 接受 `{refresh_token}`，验证后**旋转**（旧 refresh 撤销 + 签发新 access + 新 refresh）
- [ ] AC-2：`POST /api/v1/auth/logout` 要求 Bearer access token，把当前 token 的 `jti` 加入 blacklist，立即生效
- [ ] AC-3：logout 后再用同一个 access token 调 `/auth/whoami` 返回 401 `TOKEN_REVOKED`
- [ ] AC-4：refresh 端点接受 access token 必须 401 `WRONG_TOKEN_TYPE`
- [ ] AC-5：refresh 后旧 refresh_token 再次提交必须 401 `TOKEN_REVOKED`（旋转）
- [ ] AC-6：错误码统一 `MISSING_TOKEN` / `INVALID_REFRESH_TOKEN` / `WRONG_TOKEN_TYPE` / `TOKEN_EXPIRED` / `TOKEN_REVOKED`
- [ ] AC-7：单测 + 集成测试 ≥ 12 个，全绿
- [ ] AC-8：现有 886 passed 测试**零回归**

## 设计

### 1. 流程

```
[已登录用户]
  ├─ 调用业务 API → POST /chat/full + Bearer access_token
  │   └─ 401 TOKEN_EXPIRED（access 过期）
  │
  ├─ 调 POST /auth/refresh
  │   Body: { refresh_token: "eyJ..." }
  │   校验: typ == "refresh", 未过期, 未撤销
  │   Revoke: jti_old_refresh
  │   Issue: new_access_token (1h) + new_refresh_token (30d, new jti)
  │   Return: { access_token, refresh_token, token_type, expires_in, parent_id }
  │
  └─ 调 POST /auth/logout
      Header: Authorization: Bearer access_token
      校验: deps(get_current_parent) 正确取到 parent
      行为: blacklist.revoke(jti_access)
      Return: { status: "logged_out" }
```

### 2. 旋转刷新（Refresh Token Rotation）

每次 refresh 都**签发新 refresh + 撤销旧 refresh**。原因：
- 旧 refresh 一旦泄漏，泄漏者没法再次使用
- 减少长寿命 token 的暴露窗口

`niki/auth/token_blacklist.py` 需要支持 refresh token 撤销（hash by jti）。

### 3. 风险

| 风险 | 缓解 |
|------|------|
| 旋转并发问题（A 刷新 + B 用旧 refresh） | 后者失败是预期，因为前者的 refresh 已经撤销 |
| blacklist 重启丢失 | 与 BE-AUTH-001 同：in-memory 单实例够用；Redis 在 §P2 |
| 时区 / 时钟漂移 | jwt_service 全用 `int(time.time())`，明确 UTC |
| access 过期 / refresh 撤销 race | 客户端必须 catch 401 + 重走 login 流程 |

### 4. 端点签名

```
POST /api/v1/auth/refresh
Body: { "refresh_token": "eyJ..." }
→ 200 {
    "access_token": "eyJ...",
    "refresh_token": "eyJ...",
    "token_type": "Bearer",
    "expires_in": 3600,
    "parent_id": "abc123..."
  }
→ 401 { "error": "INVALID_REFRESH_TOKEN" | "WRONG_TOKEN_TYPE" | ... }

POST /api/v1/auth/logout
Header: Authorization: Bearer <access_token>
→ 200 { "status": "logged_out", "revoked_jti": "uuid..." }
→ 401 { "error": "MISSING_TOKEN" | "TOKEN_REVOKED" | ... }
```

### 5. 前端用法

```typescript
// /lib/api.ts
import axios from "axios";
import { refreshToken } from "@/lib/storage";

const api = axios.create({ baseURL: "/api/v1" });
api.interceptors.request.use((req) => {
  if (req.url !== "/auth/login" && req.url !== "/auth/refresh") {
    req.headers.Authorization = `Bearer ${getAccessToken()}`;
  }
  return req;
});

let refreshing: Promise<void> | null = null;
api.interceptors.response.use(null, async (err) => {
  if (err.response?.status === 401 && err.response.data.error === "TOKEN_EXPIRED") {
    if (!refreshing) {
      refreshing = (async () => {
        const r = await axios.post("/auth/refresh", { refresh_token: refreshToken() });
        setAccessToken(r.data.access_token);
        setRefreshToken(r.data.refresh_token);  // 旋转！
      })();
    }
    await refreshing;
    refreshing = null;
    return api.request(err.config);
  }
  return Promise.reject(err);
});
```
